# Planner report — TASK-0008 Event & Lesson Admin

Date: 2026-10-15
Plan dir: `plans/261015-2236-task0008-event-lesson-admin/`

## TL;DR

- Schema largely supports the brief; **one new Flyway migration V5 is required** — `historical_events` lacks `row_version` (lessons already has it from V3). V5 is a single `ALTER TABLE ADD COLUMN`, no data backfill.
- Lesson draft storage: reuse existing `lessons.draft_json` (JSONB, NOT NULL DEFAULT `'{}'`). No new column needed. Publish pipeline (TASK-0009) reads draft → `lesson_versions.snapshot_json`.
- Six phases, ~14h. Sequential. One writer per phase.

## Phase summary

1. **01 Shared plumbing** — V5 migration, `@Version` on `HistoricalEvent`, `Lesson`/`LessonTemplate`/`LessonVersion` entities, `LessonStatus`, 6 new domain exceptions, 3 repositories, new `ErrorCode` constants, `GlobalExceptionHandler` mappings.
2. **02 Admin Events** — `/api/v1/admin/events`: create, list (page+size+sort+status+q), detail, PATCH update, POST publish, POST archive. Slug immutable after PUBLISH. Archive blocked by `EVENT_IN_USE` when published event still has non-archived lessons.
3. **03 Admin Lessons** — `/api/v1/admin/lessons`: create (FK-validate event + enabled template), list, detail, PATCH metadata (event/template rebinding only when DRAFT), PUT draft with `expectedRowVersion` optimistic check + minimal `DraftValidator`, POST archive.
4. **04 Lesson Templates** — `/api/v1/admin/lesson-templates` list enabled + detail. Read-only per brief.
5. **05 Tests** — three new IT classes (~23 tests) + `FlywayMigrationIT` extension. Stale-`expectedRowVersion` test substitutes for flaky true-concurrency test.
6. **06 Docs** — `API_SPEC.md` admin section, `DATABASE_DESIGN.md` V5 note, `task.json` `acEvidence`.

## Decisions confirmed

- No DELETE endpoints anywhere — archive only (brief lists no delete).
- Module layout: `com.dauviet.historicalevent.admin.*` for admin event code; `com.dauviet.lesson.*` for everything lesson-related (incl. templates). Avoids new top-level `admin` module.
- `Lesson.eventId`, `templateId`, `currentVersionId` mapped as plain `UUID` columns — no `@ManyToOne` (avoids lazy-load + cross-lesson composite-FK complexity). Services validate FK existence manually.
- `draft_json`/`objectives_json`/`preset_json`/`snapshot_json` mapped as `String` + `@JdbcTypeCode(SqlTypes.JSON)`; service serialises `JsonNode` ↔ `String` via `ObjectMapper` (KISS).
- Reuse `PageResponse<T>` and sort-whitelist pattern from public `HistoricalEventController`.
- Reuse `SecurityConfig` `/api/v1/admin/**` rule — no edits needed.
- `expectedDraftRevision` from API_SPEC renamed to `expectedRowVersion` for symmetry with `@Version` field.
